## Correções na validação

`audit/validate-offline.sh` agora exige explicitamente Rust **1.98.1** em
prefixo isolado, antes de qualquer compilação. O novo
`tools/check-rust-toolchain.py` verifica rustc, cargo, rustdoc, cargo-clippy,
clippy-driver, cargo-fmt e rustfmt; recusa ferramentas externas ao prefixo e
symlinks óbvios para rustup, sem recorrer ao PATH. Executa os quatro comandos
de versão pedidos e também confere host e release do compilador. Esses
comandos só serão executados quando as ferramentas realmente estiverem presentes.

A versão mínima declarada pelo projeto continua **1.93**: exigir 1.98.1
para esta auditoria não implica elevar o MSRV do software.

O validador fixa RUSTC/RUSTDOC/RUSTFMT no prefixo aprovado e desativa wrappers
herdados que poderiam substituir o compilador [1]. Mantém caches,
`--offline --locked`, timeout por etapa e no máximo dois jobs. Registra exit
code e memória também quando uma etapa falha — antes o `set -e` impedia esse
registro final. Formatação ocorre antes de builds caros. XDG_DATA_HOME passou
a ser isolado, e todos os overrides BIGNETSCREEN_* são removidos antes dos
testes, incluindo GOP/sync/drain que o script anterior não limpava.

`tools/probe-buildenv.py` verifica compilação C, link e execução nativos,
sem inicializar GUI nem precisar dos headers configurados. Distingue o núcleo
da interface: um `.pc` que informa a versão não prova que a biblioteca real
existe. Esse probe não substitui compilação Rust, testes do programa ou
validação visual.

## Retomada

Materializar nesta conversa/executor o tarball Rust 1.98.1 original, verificar
sua integridade/procedência, ler seu instalador e instalar em prefixo isolado.
Os instaladores standalone são o método documentado para uso offline [2].
Não usar o hash apenas mencionado por um agente anterior como prova independente
de autenticidade do arquivo.

Depois da instalação real, executar:

```bash
cd bignetscreen-audit
./setup.sh
source ./build-env.sh
cd repo
python3 audit/tools/check-rust-toolchain.py --prefix /mnt/data/toolchains/rust-1.98.1
./audit/validate-offline.sh
```

O checker aceita outro prefixo por `--prefix`; o gate usa
`BIGNETSCREEN_RUST_PREFIX`. O buildenv deve ser reextraído/preparado quando
mudar de diretório: seu `setup.sh` original grava caminhos absolutos e a marca
`.prefixed` não corrige um sysroot já movido.

Para concluir link/testes/GUI do workspace, disponibilizar também as bibliotecas
GTK4, libadwaita e Graphene compatíveis em bundle isolado. Não substituir
bibliotecas do sistema. A confirmação de versão, por si, não aprova build;
`cargo test` compila e executa alvos distintos, inclusive doctests [3].

As pendências de protocolo, adaptação de bitrate, DeviceAuth e testes de
conectar/parar/reconectar em receptores reais permanecem as da revisão R1.
